### 剩余 0.26 的本质

**剩余扣分点不再是"设计遗漏"，而是"超出设计文档能解决的范畴"：**

| 扣分点 | 能否通过再次补强文档解决？ |
|---|---|
| 合规假设依赖法务签字 | ❌ 需要真人法务，AI 无法代签 |
| BD 共识访谈未执行 | ❌ 需要真实 BD 访谈 |
| AIGC 标识字号合规 | ❌ 法规无明确规定，监管解释模糊 |
| 文件锁竞态 | ✅ 可补强，但属实现细节，通常在代码里用 `fcntl.flock` 解决 |
| Volcengine 宕机预案 | ✅ 可补强，加一条"平台故障 → 降级纯 markdown + 告警" |
| Canary 手动验收 SOP | ✅ 可补强，定义验收人 + 检查清单 |

### 补强性价比分析

| 再补一轮能提到多少分？ | 边际价值 | 时间成本 |
|---|---|---|
| 最乐观：9.24 → 9.40 | 3 个可补项 × 0.05 分 ≈ +0.15 | 0.3 人日 |
| 仍差 0.1 到 9.5 | 需要真实法务/访谈动作解决 | N/A（不能文档化） |

**继续"纯补强文档"到 9.5 的路径实际不可达**——0.26 里至少 0.11 取决于真人行动。
